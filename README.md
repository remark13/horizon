# Horizon

Прототип поиска и анализа кандидатов в слабые научно-технологические сигналы.
Версия 0.4.65, 29 сентября 2026 года. Исследовательский продукт, не production.

Исходный код опубликован участником конкурса для демонстрации и проверки
прототипа. Это не официальный сервис Газпромбанка. Упоминание банка и оформление
прототипа не означают одобрения, поддержки или предоставления сервиса банком.
Публичный доступ к исходникам не означает, что проекту назначена открытая лицензия.

Пользователь задаёт направление на русском языке. Система формирует поисковый
план, собирает публикации, выделяет темы и показывает до 15 кандидатов на
странице. В карточке доступны источники, расчёт оценки и динамика. Экспертиза
необязательна. Публичные подборки отделены меткой происхождения.

## Установка с нуля

### 1. Получите исходники

При установленном Git:

```sh
git clone https://github.com/remark13/horizon.git
cd horizon
```

Без Git откройте [репозиторий](https://github.com/remark13/horizon), выберите
**Code → Download ZIP** и распакуйте архив. GitHub добавляет имя ветки к папке,
например `horizon-main`. Отдельный подготовленный архив может содержать папку
`horizon`. Откройте терминал именно в папке, где рядом лежат `compose.yaml`,
`pyproject.toml` и `.env.repository.example`. Не запускайте команды из
`docs/repository` или `infra`. Основной переносимый профиль находится в корне.

### 2. Проверьте Docker и ресурсы

Нужны работающий Docker Engine / Docker Desktop с Compose v2 и интернет:
реестры Docker, PyPI, индекс CPU-пакетов PyTorch, Hugging Face и выбранные
источники публикаций должны быть доступны. Python на компьютере не нужен
для контейнерного запуска, он нужен только для необязательного генератора `.env`.

```sh
docker info
docker compose version
```

Ориентиры для планирования ресурсов, **не измеренные минимальные требования**:

| Профиль | Ресурсы, выделенные Docker | Свободное место |
| --- | --- | --- |
| Первый запуск и небольшой научный запрос | Около 4 CPU и 8 ГБ памяти | Около 20–30 ГБ |
| Небольшой исследовательский пилот с запасом | Около 4–8 CPU и 12–16 ГБ памяти | Около 40–60 ГБ |

Фактический расход зависит от размера выборки, моделей и накопленных результатов.
Полное зеркало научных баз в эти ориентиры не входит. В Docker Desktop проверьте
раздел ресурсов и оставьте память для основной системы. По умолчанию worker
ограничен 2 CPU и 6 ГБ памяти. Это лимит одного контейнера, а не потребность
всего приложения: PostgreSQL и веб-сервис работают отдельно. Значения worker
задаются в `.env` как `HORIZON_WORKER_CPUS` и `HORIZON_WORKER_MEMORY`.
Проверенные платформы и границы проверки описаны в [VALIDATION.md](VALIDATION.md).

### 3. Создайте личный файл настроек

На Linux/macOS:

```sh
cp .env.repository.example .env
```

На Windows в PowerShell:

```powershell
Copy-Item .env.repository.example .env
```

Перед копированием убедитесь, что собственного `.env` ещё нет. Откройте созданный
файл редактором и **обязательно задайте `POSTGRES_PASSWORD`: случайные буквы
и цифры, минимум 24 символа**. Пустое значение блокирует запуск. Не используйте
демонстрационный пароль, пароль GitHub или пароль прежней рабочей базы.
Файл `.env` не следует коммитить, загружать в GitHub или пересылать с логами.

Если установлен Python 3, вместо копирования и ручного пароля выполните один раз:

```sh
python3 scripts/init_repository_env.py
```

Скрипт создаёт `.env` со случайным паролем и отказывается перезаписывать
существующий файл. На Windows команда Python может называться `py -3`.
Достаточно одного из двух способов, последовательно выполнять оба не нужно.

Если на компьютере уже есть другой Compose-проект `horizon`, до первого
запуска задайте отличающееся `HORIZON_PROJECT_NAME` и свободный `HORIZON_PORT`.
Так установки не используют одни и те же тома и порт. Новый проект создаёт
пустую PostgreSQL, старая рабочая база автоматически не переносится.

Ключи и проверка источников описаны в [SOURCE_SETUP.md](SOURCE_SETUP.md).
Без них можно открыть интерфейс и встроенные публичные подборки. Доступность
живого поиска и отдельных источников зависит от их правил, ключей и лимитов.

### 4. Соберите и запустите

```sh
docker compose --env-file .env config --quiet
docker compose --env-file .env up --build -d
docker compose --env-file .env ps
```

Дождитесь статуса `healthy` у `db` и `app`, а у `worker` статуса `Up`
или `running`. При необходимости повторите последнюю команду. На первом
запуске скачиваются образы и пакеты, затем создаются таблицы и применяются
миграции. Веса SPECTER2 загружаются отдельно при первом научном анализе.
Это не гарантированно укладывается в 20 минут: лимит ожидания пользовательского
запроса не относится к установке и первой загрузке моделей.

Проверьте ответ приложения, не устанавливая дополнительные программы на хост:

```sh
docker compose --env-file .env exec -T app python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8080/health', timeout=10).read().decode())"
```

Ожидается успешный ответ JSON с версией Horizon. Это проверка HTTP-сервиса,
не проверка доступа ко всем источникам или выполнения научного анализа.
Для диагностики:

```sh
docker compose --env-file .env logs --tail=100 db app worker
```

Откройте [рабочее место скаута](http://127.0.0.1:8085/scout),
[публичные подборки](http://127.0.0.1:8085/public-signals) и
[справку](http://127.0.0.1:8085/help). Если изменили `HORIZON_PORT`, замените
`8085` в адресах. Доступ ограничен текущим компьютером. Публикация исходников
на GitHub не запускает сервис в интернете.

### 5. Выполните короткую приёмку

1. Убедитесь, что открываются справка и встроенный каталог публичных сигналов.
2. Настройте доступные источники по [SOURCE_SETUP.md](SOURCE_SETUP.md).
3. В рабочем месте скаута задайте, например, «Беспилотные авиационные системы».
   Дождитесь сбора и анализа. На новой установке предыдущих результатов нет.
4. При наличии кандидатов откройте карточку, проверьте ссылки на публикации,
   объяснение оценки и доступные графики. Недостающие данные не должны
   восприниматься как нулевые показатели.
5. При желании выберите записи и создайте заявку на экспертизу.
   Заявка сохраняется внутри Horizon, внешние уведомления не отправляются.

Пустой ответ источника, ошибка доступа или нулевая выдача не доказывают отсутствие
слабых сигналов. Зафиксируйте запрос и состояние источников, проверьте логи.
Эта приёмка проверяет пользовательский путь, но не измеряет научную точность
и не подтверждает SLA. Не размещайте экспертные персональные данные в тестовой
установке, доступ к которой планируется открыть.

## Настройки, остановка и типовые проблемы

После изменения ключей, модели или лимитов worker в `.env` пересоздайте
контейнеры приложения и worker, сохранив тома:

```sh
docker compose --env-file .env up -d --force-recreate app worker
```

`stop/start` и `restart` не применяют новые переменные окружения к уже созданным
контейнерам. Изменение `POSTGRES_PASSWORD` в файле также **не меняет пароль
в существующей PostgreSQL**. Для рабочей базы нужна отдельная согласованная
смена пароля в БД и настройках, а не удаление данных.

Для обычной паузы и продолжения работы без изменения настроек:

```sh
docker compose --env-file .env stop
docker compose --env-file .env start
```

Эти команды сохраняют данные. **Не выполняйте `docker compose down -v`, если
нужно сохранить базу и результаты.** Новая установка не содержит старых поисков
или экспертных заявок.

| Что произошло | Что проверить |
| --- | --- |
| Docker не найден или не отвечает | Установите и запустите Docker Engine / Desktop, затем повторите `docker info`. |
| Ошибка `POSTGRES_PASSWORD` при проверке Compose | В корне проекта должен быть именно файл `.env`, не `.env.txt`, с непустым случайным паролем. |
| Порт 8085 занят | Задайте свободный `HORIZON_PORT` в `.env` и пересоздайте `app` и `worker` указанной выше командой. |
| Образы, пакеты или модели не скачиваются | Проверьте интернет, доступ к соответствующему реестру и место на диске. Зафиксируйте ошибку. Не отключайте проверку TLS. |
| `db` или `app` остаётся `unhealthy`, worker перезапускается | Посмотрите `logs --tail=100 db app worker`. Проверьте место, доступную Docker память и миграции. Не удаляйте тома для «лечения» ошибки. |
| Интерфейс работает, но материалы не собираются | Проверьте источник и ключ по [SOURCE_SETUP.md](SOURCE_SETUP.md). Готовность интерфейса не означает доступность внешнего API. |
| После изменения ключа ничего не поменялось | Выполните `up -d --force-recreate app worker`, а не только `restart`. Не публикуйте значение ключа в диагностике. |
| Первый анализ долго загружает модель | Проверьте логи worker и доступ к Hugging Face. Не запускайте несколько одинаковых заданий одновременно. |

## Что входит

- FastAPI, PostgreSQL/pgvector, фоновый worker, интерфейс и справка.
- Научный поиск OpenAlex/arXiv, нормализация, тематические и временные метрики.
- Коннекторы внешних материалов с явными ограничениями доступа.
- Карточки, графики, публичные подборки, экспертиза, радар, PESTLE и выгрузка.
- Миграции, исходники, конфигурации, переносимые тесты и GitHub Actions.
- Контрольная сумма каждого файла в `MANIFEST.json` исходного архива.

Подключённый коннектор не гарантирует доступность API. Ключи и права для
OpenAlex, EPO OPS, Lens, Event Registry и других каналов настраиваются отдельно.
Скопированные каталоги не означают права на повторную публикацию полных
текстов источников. Список условий: [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Что не входит и не обещается

Нет рабочей БД, клиентских таблиц и производного каталога 100 примеров,
пакетов экспертной разметки, PDF, полного arXiv/OpenAlex, весов моделей,
паролей и истории Git. Исследовательские сценарии, требующие этих материалов,
не воспроизводятся одним архивом. История исследований остаётся в исходном
рабочем проекте, а не смешивается с чистым репозиторием.

Переносимый режим использует ограниченный живой сбор без обязательного
локального arXiv. Он не равен покрытию большого локального корпуса. Пустая
выборка или ограничение API не доказывают отсутствие сигнала. Полный анализ
большого корпуса требует отдельной подготовки ресурсов.

Точность детектора, вероятность успеха технологии и соблюдение SLA на любом
оборудовании не доказаны. Балл 0–100 является рабочей оценкой ранжирования.
Отдельная оболочка для внешнего показа доступна только для чтения и с паролем,
это не многопользовательский production и не полноценный публичный поиск.

## Публикация в GitHub для конкурса

Владелец разрешил **публичный репозиторий** для участия в конкурсе. Публикуется
подготовленная папка `horizon` без старой истории Git. Не загружайте рабочую папку целиком и не используйте
`git add .` в исходном исследовательском проекте.

В распакованной папке после просмотра состава:

```sh
git init
git add .
git diff --cached --stat
git status --short
# Просмотрите состав и только затем создайте первый commit и настройте remote.
```

Выбор лицензии отложен владельцем. В этом комплекте лицензия не назначается.

кода, сторонних данных или брендинга за пределами применимых условий.
