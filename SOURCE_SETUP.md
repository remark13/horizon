# Настройка источников Horizon

Инструкция для переносимого комплекта 0.4.65. Код и официальные страницы поставщиков сверены 29 сентября 2026 года. Условия доступа могут изменяться. Наличие коннектора не означает, что конкретная учётная запись уже получила доступ.

## 1. Что нужно для первого запуска

Для запуска интерфейса и базы обязателен только собственный `POSTGRES_PASSWORD` в локальном `.env`. Ключи источников не нужны для открытия приложения и просмотра встроенных публичных подборок. Для нового научного поиска нужны интернет, доступность OpenAlex/arXiv и загрузка выбранной модели. Набор публикаций в новой установке не равен большому локальному корпусу разработчика.

| Источник | Для чего используется | Что заполнить в .env | Обязательность |
| --- | --- | --- | --- |
| OpenAlex | Основной научный поиск | `OPENALEX_API_KEY`, при желании `OPENALEX_MAILTO` | Ключ настоятельно рекомендуется для регулярного поиска. По текущей официальной документации базовый доступ без ключа существует, но ограничен |
| arXiv | Основной научный поиск препринтов | Ключ не требуется | Живой API включён в переносимом Compose. Полное локальное зеркало не входит в поставку |
| EPO OPS | Патентные публикации | `EPO_OPS_CONSUMER_KEY` и `EPO_OPS_CONSUMER_SECRET` | Оба значения обязательны именно для этого коннектора |
| Lens | Дополнительный патентный поиск | `LENS_API_TOKEN` | Обязателен токен с разрешённым Patent API, не только аккаунт на сайте |
| Event Registry / NewsAPI.ai | Новостные публикации | `EVENT_REGISTRY_API_KEY` | Обязателен действующий ключ и доступный бюджет запросов |
| Semantic Scholar | Дополнительные научные метаданные | `SEMANTIC_SCHOLAR_API_KEY` | Необязателен для используемого поиска, но рекомендуется из-за ограничений анонимного доступа |
| Media Cloud | Новости из выбранных коллекций СМИ | `MEDIACLOUD_API_KEY` и `MEDIACLOUD_COLLECTION_IDS` | Нужны ключ и от 1 до 10 явных ID коллекций |

Патенты и новости дополняют карточки. Semantic Scholar не становится автоматически третьим независимым научным подтверждением: одна статья может присутствовать сразу в нескольких базах. Отсутствующий ключ или недоступный API нельзя интерпретировать как отсутствие публикаций, патентов или новостей.

## 2. Где хранить настройки

1. Работайте в корне переносимого репозитория, рядом с `compose.yaml`.
2. Если `.env` ещё нет, выполните `python3 scripts/init_repository_env.py`. Скрипт создаёт пароль базы и не перезаписывает существующий файл. Альтернатива описана в README.
3. Откройте локальный `.env` в редакторе и заполните только нужные переменные из таблицы. Не редактируйте шаблон `.env.repository.example`, чтобы не отправить реальные значения в GitHub.
4. Не заменяйте пароль уже созданной PostgreSQL ради настройки API. Смена переменной не меняет пароль существующей базы автоматически.
5. Сохраните файл и пересоздайте только приложение и обработчик задач:

```sh
docker compose --env-file .env up -d --no-deps --force-recreate app worker
docker compose ps
```

Простой `docker compose restart` не передаёт новые значения окружения. Команду выше выполняйте после завершения активного анализа: пересоздание обработчика прерывает выполняемую работу. База и её тома не удаляются. После изменения только ключей пересборка образа не нужна.

Не публикуйте `.env`, снимки экрана с ключами, вывод `docker compose config`, полный `docker inspect` или содержимое окружения. Эти диагностические команды могут раскрыть секреты. Не передавайте ключи в чат, issue, презентацию или URL. Если ключ попал в публичный репозиторий, отзовите его у поставщика. Удаление файла из последнего коммита не убирает секрет из истории.

## 3. OpenAlex

Получите личный ключ самостоятельно в [настройках OpenAlex](https://openalex.org/settings/api) и внесите его в `OPENALEX_API_KEY`. Поле `OPENALEX_MAILTO` предназначено для контактной почты. Оно не заменяет ключ. Если это поле пустое, научный коннектор использует `SAIA_MAILTO`, если оно задано.

Текущая [официальная инструкция авторизации](https://help.openalex.org/api/authentication/) допускает простые запросы без ключа и рекомендует бесплатный ключ для большего бюджета. Ранее действовали другие правила, поэтому не ориентируйтесь на старые пересказы. В Horizon ключ отправляется в заголовке авторизации, не в поисковой ссылке.

Сначала выполните один тест из раздела 10 с `SOURCE = "openalex"`. Успешный ответ означает доступность ограниченного поиска, а не полное покрытие области. При HTTP 429 остановите повторные прогоны и проверьте лимит в аккаунте. Контактная почта и ключ не устраняют квоты, задержки индексации или неполные аннотации.

## 4. arXiv

Для используемого API ключ не нужен. Официальные [руководство](https://info.arxiv.org/help/api/user-manual.html) и [условия API](https://info.arxiv.org/help/api/tou.html) описывают поиск метаданных. Соблюдайте паузу не менее трёх секунд между последовательными обращениями. Не запускайте одновременно несколько тестов или загрузчиков arXiv.

В `compose.yaml` явно задано `SAIA_ALLOW_LIVE_ARXIV: "1"`. Это режим ограниченного запроса к API, не скачивание всего архива. Не добавляйте эту переменную в `.env` с ожиданием переключения режима: в данном Compose её значение закреплено напрямую.

Локальное зеркало подключается отдельно с настройкой пути и доступного контейнерам тома. Одного адреса папки на компьютере недостаточно. Корпус, индексы и права на использование полных текстов не поставляются вместе с исходным кодом.

Проверка: `SOURCE = "arxiv"` в разделе 10. Пустой ответ не доказывает отсутствия исследований. Ошибка доступа или пауза сервера не должна заменяться выдуманными результатами.

## 5. EPO Open Patent Services

Откройте [официальную страницу OPS](https://www.epo.org/en/searching-for-patents/data/web-services/ops), самостоятельно зарегистрируйтесь и создайте приложение в кабинете поставщика. После получения доступа заполните оба поля:

- `EPO_OPS_CONSUMER_KEY`
- `EPO_OPS_CONSUMER_SECRET`

Это не логин и пароль от Espacenet. Horizon самостоятельно обменивает пару на временный OAuth access token. Его вручную сохранять в `.env` не нужно.

Официальная [документация OPS 3.2](https://link.epo.org/web/searching-for-patents/data/en-ops-v3.2-documentation-version-1.3.20.pdf) описывает создание пары и OAuth. Квоты и условия использования смотрите на странице OPS. Платную подписку Horizon не оформляет.

Проверка: `SOURCE = "epo_ops"`. Один тест выполняет авторизацию и один небольшой патентный поиск. Без любого из двух значений ожидается `credentials_required`, а не работающий патентный канал. Полученные патентные публикации не доказывают внедрение, правовую действительность патента или рыночный успех технологии.

## 6. Lens Patent API

Войдите в собственный профиль Lens, запросите именно доступ к Patent API и после его одобрения создайте токен. Внесите токен в `LENS_API_TOKEN`.

[Getting Started](https://docs.api.lens.org/getting-started.html) прямо разделяет одобрение API-доступа и выпуск токена. Учётная запись для поиска на сайте сама по себе недостаточна. [Документация Lens](https://docs.api.lens.org/) также указывает требования атрибуции при публичном показе данных. Перед внешним показом соблюдите применимые условия, включая требуемую поставщиком атрибуцию. Настоящая инструкция не подтверждает юридическую готовность такого показа.

Проверка: `SOURCE = "lens_patents"`. Коннектор делает ограниченный поиск по названию или аннотации патента и сохраняет метаданные, а не тексты формулы изобретения. При истечении токена или отсутствии права Patent API ответ может быть 401/403. При исчерпании квоты возможен 429. Не увеличивайте количество повторов вместо проверки кабинета.

## 7. Event Registry / NewsAPI.ai

Откройте [официальный сайт NewsAPI.ai](https://newsapi.ai/) и получите ключ в собственной учётной записи. Это Event Registry, а не другой сервис с похожим названием NewsAPI.org. Внесите значение в `EVENT_REGISTRY_API_KEY`.

[Официальные примеры запросов](https://www.newsapi.ai/documentation/examples) и [описание авторизации поставщика](https://eventregistry.org/blog/leveraging-the-power-of-rest-api-with-news-api-using-eventregistry-org/) показывают использование API key. Доступ к архиву, количество запросов и стоимость зависят от плана. Бесплатное или неограниченное обслуживание не обещается.

Проверка: `SOURCE = "event_registry"`. Horizon запрашивает небольшую страницу новостных метаданных, не полный архив и не полные тексты статей. Токен передаётся в теле HTTPS-запроса. Не сохраняйте и не публикуйте тело исходящего запроса. Даже одна найденная новость может оказаться перепечаткой или нерелевантным совпадением, поэтому доступность канала и качество доказательств проверяются отдельно.

## 8. Semantic Scholar

Для используемого поиска `paper/search` ключ можно сначала оставить пустым. По [официальному описанию API](https://webflow.semanticscholar.org/product/api) анонимные пользователи делят общий ресурс и могут получать дополнительные ограничения. Для регулярной работы подайте собственную заявку на API key и заполните `SEMANTIC_SCHOLAR_API_KEY`.

Проверка: `SOURCE = "semantic_scholar"`. Ключ передаётся в заголовке `x-api-key`. Подключение не означает автоматического включения всех найденных статей в основной корпус: текущая роль коннектора состоит в дополнительном библиографическом контексте карточки. Цитирования относятся к моменту получения, а не восстанавливают историческое состояние базы.

Сверяйте [условия использования данных](https://api.semanticscholar.org/license/) перед публичным показом или передачей. Доступ к API и разрешение на любой последующий способ использования не равнозначны.

## 9. Media Cloud

Самостоятельно получите ключ через [Media Cloud Search](https://search.mediacloud.org/). Внесите его в `MEDIACLOUD_API_KEY`. Затем выберите необходимые коллекции в [Media Cloud Directory](https://www.mediacloud.org/media-cloud-directory) и укажите их числовые идентификаторы в `MEDIACLOUD_COLLECTION_IDS` через запятую.

Horizon принимает от 1 до 10 различных положительных числовых ID, каждый не длиннее 10 цифр. Названия стран, URL коллекций, пустое значение или повторяющиеся ID не подходят. Используйте реальные ID выбранных коллекций, не случайные числа из примера.

Официальные [Search API guide](https://www.mediacloud.org/documentation/search-api-guide) и [клиент Media Cloud](https://github.com/mediacloud/api-client) описывают доступ и коллекции. Horizon использует собственный небольшой запрос к `/api/search/sample`, а не полный клиент и не выгрузку всего архива.

Проверка: `SOURCE = "mediacloud_news"`. Без ключа возвращается `credentials_required`. При заданном ключе, но отсутствующем или неверном списке коллекций возвращается `collection_ids_required`. Это проверка заполнения настроек, не действительности ключа или существования коллекций. Совместимость текущего ответа API окончательно проверяется только живым запросом с доступом пользователя.

Результат зависит от состава выбранных СМИ, языка и периода. Маленькая выборка не является полной статистикой публикаций и не позволяет считать отсутствующий результат нулевой новостной активностью.

## 10. Безопасные минимальные проверки

### Проверка присутствия настроек без обращения к поставщикам

Выполните после пересоздания контейнеров. Команда показывает только наличие значений и локальный статус трёх агрегаторов. Она не выводит секреты, не проверяет их действительность и не загружает публикации.

```sh
docker compose --env-file .env exec -T app python - <<'PY'
import os
from saia.aggregator_evidence import configuration_status
names = (
    "OPENALEX_API_KEY", "EPO_OPS_CONSUMER_KEY", "EPO_OPS_CONSUMER_SECRET",
    "LENS_API_TOKEN", "EVENT_REGISTRY_API_KEY", "SEMANTIC_SCHOLAR_API_KEY",
    "MEDIACLOUD_API_KEY", "MEDIACLOUD_COLLECTION_IDS",
)
for name in names:
    print(name, "задано" if os.environ.get(name, "").strip() else "не задано")
for source in ("lens_patents", "event_registry", "mediacloud_news"):
    print(source, configuration_status(source))
PY
```

При подозрении на разные настройки приложения и обработчика повторите команду, заменив `app` на `worker`. Оба сервиса должны получать значения из одного `.env`.

### Один живой тест одного источника

Пример ниже предназначен для macOS/Linux или WSL. Перед каждым запуском изменяйте только строку `SOURCE` на один из идентификаторов из предыдущих разделов. По умолчанию проверяется arXiv. Запрашивается не более одной записи за последние 30 дней. Для Semantic Scholar серверный фильтр задаётся по годам, после ответа Horizon дополнительно проверяет даты.

Это диагностический запрос к поставщику, он может расходовать его квоту. Он не запускает кластеризацию, не скачивает модель и не сохраняет результаты в базу. Некоторые коннекторы могут повторить ограниченный запрос после 429. EPO сначала выполняет отдельный запрос авторизации. Не запускайте тест в цикле.

```sh
docker compose --env-file .env exec -T app python - <<'PY'
from datetime import datetime, timedelta, timezone
import httpx

SOURCE = "arxiv"
today = datetime.now(timezone.utc).date()
start = today - timedelta(days=30)
phrase = "robotics"

try:
    if SOURCE in ("openalex", "arxiv"):
        from saia.discovery import collect_openalex, collect_arxiv
        collect = collect_openalex if SOURCE == "openalex" else collect_arxiv
        with httpx.Client(timeout=20.0, follow_redirects=False) as client:
            rows = collect(client, phrase, start, today, 1)
        print(SOURCE, "complete" if rows else "empty_observed_response",
              "records", len(rows))
    else:
        if SOURCE == "epo_ops":
            from saia.patent_evidence import PatentQuery, fetch
            result = fetch(PatentQuery("source-setup-check", phrase, start,
                                      today, today, 1), timeout=12.0)
        elif SOURCE == "semantic_scholar":
            from saia.scholar_evidence import ScholarQuery, fetch
            result = fetch(ScholarQuery("source-setup-check", phrase, start,
                                       today, today, 1), timeout=12.0)
        elif SOURCE in ("lens_patents", "event_registry", "mediacloud_news"):
            from saia.aggregator_evidence import AggregatorQuery, fetch
            result = fetch(AggregatorQuery("source-setup-check", SOURCE, phrase,
                                          start, today, today, 1), timeout=12.0)
        else:
            raise ValueError("Unknown source")
        rows = result.get("observations")
        code = result.get("http_status")
        if code is None:
            code = result.get("request", {}).get("http_status")
        print(SOURCE, result.get("status"), "records",
              len(rows) if isinstance(rows, list) else "unknown", "HTTP", code)
except Exception as error:
    response = getattr(error, "response", None)
    print(SOURCE, "check_failed", type(error).__name__,
          "HTTP", getattr(response, "status_code", None))
PY
```

Не дописывайте `print(result)`, вывод заголовков или полный traceback. Подробный ответ не нужен для проверки доступа. В PowerShell эти многострочные команды напрямую не копируйте: используйте WSL или попросите администратора выполнить эквивалентную проверку внутри контейнера.

| Результат | Что это означает | Следующее действие |
| --- | --- | --- |
| `complete` и одна запись | Один ограниченный запрос обработан | Проверить содержимое и релевантность в карточке. Это не проверка полноты источника |
| `empty_observed_response` | Ответ обработан, подходящих записей в этой выборке нет | Проверить тему, даты и охват. Не трактовать как отсутствие технологии |
| `credentials_required` | Не заполнены необходимые поля | Добавить свои значения и пересоздать app/worker |
| `collection_ids_required` | Не заполнен корректный список коллекций Media Cloud | Уточнить ID в Directory |
| `credentials_rejected`, HTTP 401/403 | Ключ, права или политика доступа не позволяют выполнить запрос | Проверить аккаунт, срок токена и разрешённый API |
| `rate_limited` или HTTP 429 | Исчерпана квота либо слишком высокая частота | Дождаться разрешённого времени повтора, проверить кабинет. EPO может показать этот код как `source_http_error` |
| `source_unavailable`, `source_http_error`, `check_failed` | Сеть, таймаут, сервер или другой технический отказ | Зафиксировать только источник, время и код. Проверить доступность без многократных повторов |
| `invalid_source_response` | Ответ не соответствует ожидаемой структуре | Передать разработчику статус и источник. Не публиковать сырой ответ или ключ |

Статус `requestable` в локальной проверке означает лишь возможность попытки обращения. Он не подтверждает работоспособность API.

## 11. Как проверить источник в пользовательском сценарии

После успешного маленького теста выполните обычный запрос в Horizon, откройте одну карточку и выберите нужный источник в блоке внешних материалов. На первой проверке включайте по одному каналу, не весь каталог. Проверьте название, дату, ссылку и метку происхождения найденного материала.

Подключение ключа не гарантирует автоматический выбор всех провайдеров. Для пакетного обогащения по умолчанию используются Google News RSS, один патентный канал и публичная выборка Dealroom. Текущая логика выбирает Lens вместо EPO, только если задан `LENS_API_TOKEN` и не задан `EPO_OPS_CONSUMER_KEY`. Если задан лишь EPO key без secret, EPO останется выбранным, но работать не сможет. Заполните оба поля или явно выберите Lens.

Контекст карточки кешируется: успешный или пустой ответ до 24 часов, ошибка до 5 минут. Сразу после исправления ключа старое сообщение об ошибке может сохраняться до истечения короткого кеша. Изолированный тест из раздела 10 проверяет поставщика напрямую, не этот кеш.

`/health` проверяет приложение, но не доступ к внешним источникам, остаток квот или качество поиска. Наличие материалов в карточке также не равно подтверждённому слабому сигналу. Новости, патенты, инвестиционные сообщения и научные статьи сохраняют разные роли.

## 12. Границы этой инструкции
