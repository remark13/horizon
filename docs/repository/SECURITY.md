# Безопасность поставки и доступа

## Границы

Рабочий исследовательский API не имеет production-аутентификации, ролей,
изоляции пользователей, ограничений бюджета по пользователю и полного
аудита безопасности. Не открывайте локальный порт напрямую в интернет.
Пароль PostgreSQL не защищает HTTP API.

Переносимый Compose публикует приложение только на loopback, не публикует
порт PostgreSQL и использует отдельные именованные тома. Исходная рабочая
база и её экспертные заявки не входят в репозиторий.

`saia.demo_server` предназначен для отдельного защищённого просмотра.
У него обязательный пароль, запрет операций записи, ограниченный набор
GET-маршрутов и закрытые документы API. По умолчанию рабочая база не
используется. Общий пароль не заменяет персональные роли. Нельзя передавать
пароль через URL или хранить его в Git.

## До внешнего доступа

- Подготовить отдельные демонстрационные данные без личных и клиентских сведений.
- Проверить права на публичное представление материалов и брендинга.
- Использовать HTTPS и сильный пароль, передавать ссылку и пароль раздельно.
- Не пробрасывать напрямую 8082/8084, а только отдельную защищённую точку входа.
- Ограничить время демонстрации и остановить туннель после неё.
- Для полноценного публичного поиска добавить аутентификацию, роли, лимиты
  одновременных заданий, бюджет внешних API, мониторинг и резервное копирование.

## Проверка архива

`scripts/build_repository_bundle.py` использует список включаемых папок,
отбрасывает symlink/private-каталоги, рабочие документы, базы, ключи и корпуса.
Проверяет известные секреты из окружения и `.env`, а также несколько обычных
форматов токенов. При совпадении упаковка останавливается без вывода значения.
Это не доказательство полного отсутствия секретов и не аудит старой истории Git.

`MANIFEST.json` содержит хеш каждого файла. `--verify --output archive.zip`
проверяет пути, отсутствие дубликатов, CRC и SHA-256. Сборщик не перезаписывает
существующий архив. Для новой редакции задавайте новое имя.

Некоторые старые исследовательские скрипты содержат пути прежней машины.
Их список есть в `MANIFEST.json`, раздел `machine_path_review_files`.
Они не используются новым переносимым запуском. Не запускайте старый сценарий
без проверки его входов и выходов.
