# Проверка репозитория 0.4.65

## Переносимый набор тестов

```sh
python -m pip install '.[dev,db,web,bulk]'
python scripts/check_repository.py
```

Для поведенческих проверок браузерного JavaScript нужен Node.js в PATH
или переменная `HORIZON_NODE_BINARY`. GitHub Actions устанавливает Node.js.
Тесты из `check_repository.py` покрывают API-контракты, оценки, публичные
подборки, справку, передачу на экспертизу, защитную оболочку, упаковку,
Compose и ограниченный переносимый научный сбор.

`pytest -q` во всём исследовательском проекте — более широкий набор. Часть
старых тестов требует исключённых клиентских каталогов, evaluation packets,
mission history, PDF и больших локальных корпусов. Поэтому полный исторический
прогон не является тестом минимального архива. Отсутствие этих данных не
заполняется вымышленными примерами. Проверка хеша JRC PDF отдельно помечена
`local_data` и пропускается без исходного PDF; структура карточек проверяется всегда.

## Ограничения доказательства переносимости

Ранее проверенное окружение: Linux arm64, Python 3.12, точные версии
`infra/constraints.docker-arm64-py312.txt`. Это не lock с хешами всех колёс.
Сборка на amd64 и полная установка зависимостей из сети на чужой машине
должны проверяться отдельно. GitHub Actions настроен, но удалённый прогон
невозможен до загрузки репозитория.

Изолированная проверка запуска использует отдельную папку распакованного
архива, новую PostgreSQL и отсутствие bind-mount рабочего проекта. Допустимое
ускорение: существующий образ зависимостей через `HORIZON_BASE_IMAGE` и
`HORIZON_INSTALL_DEPENDENCIES=0`, затем проверка всех закреплённых версий.
Это доказывает наличие файлов и старт из пустой БД, но не скачивание пакетов
с нуля и не воспроизведение прежних научных результатов.

Самостоятельный живой запрос зависит от внешних API, ключей, лимитов,
сетевой доступности и первого скачивания моделей. Ограниченные API-выборки
не приравниваются к полному зеркалу. Численные результаты исторического
локального прогона не переносятся автоматически в пустую установку.

Архив проверяется сборщиком по CRC, относительным путям, составу и SHA-256.
Конкретные итоги выполненной проверки фиксируются ниже перед передачей.

## Выполнено 29.09.2026

- Переносимые проверки из распакованного комплекта на Python 3.14 и с Node.js:
  **363 passed, 4 skipped**. Пропуски: два исторических пакета разметки,
  исходный PDF JRC и модуль интеграции без строки подключения к БД.
- В отдельном контейнере с новой PostgreSQL интеграционные проверки:
  **76 passed, 1 skipped**. Единственный пропуск требует внешнего исходного
  исследовательского пакета, который не входит в репозиторий.
- Docker-образ собран из изолированной распакованной папки. Переиспользован
  только локальный образ зависимостей, проверено совпадение **65 закреплённых
  версий**. Исходники импортируются из `/opt/horizon`, не из старого `/app`.
- Созданы собственные Docker-тома. Новая пустая БД получила **67 миграций**,
  ожидающих миграций нет. `/health` вернул версию **0.4.65**, каталог содержит
  **361 активную запись**. App healthy, worker запускался без старого корпуса.
- Проверка справки и демонстрационного шлюза не зависит от БД. Защитный слой
  отдельно проверен на реальном приложении с запрещённым обращением к БД:
  разрешённые страницы доступны, неизвестные пути и операции записи закрыты.
- CRC и SHA-256 файлов исходного ZIP проверены. Автоматическая проверка токенов
  не обнаружила совпадений в выбранных файлах. Полноценный аудит безопасности
  и прав на все данные не заявляется.

Рабочая база на 8082 не использовалась для тестовых записей. Внешний туннель,
публичный хостинг и GitHub-публикация не запускались. Сквозной живой поиск
на полностью новой машине с загрузкой моделей не подтверждён этим тестом.
